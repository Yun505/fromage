# Schema
 
Source of truth for data shapes. Code in `shared/types.ts` implements exactly this.
 
## Cheese
 
| Field | Type | Notes |
|---|---|---|
| `cheeseId` | string | UUID, generated at seed time |
| `name` | string | |
| `milk` | `MilkType[]` | can be a blend, e.g. `["cow", "goat"]` |
| `moisture` | `Moisture \| null` | one of: fresh, soft, semi-soft, semi-hard, semi-firm, firm, hard. `null` if source data was `NA` |
| `processTags` | `ProcessTag[]` | e.g. `["artisan", "brined"]` — how the cheese is made, separate from moisture |
| `region` | `string \| null` | |
| `country` | `string \| null` | |
| `texture` | `string[]` | e.g. `["creamy", "dense", "firm"]` |
| `flavorProfile` | `string[]` | |
| `aroma` | `string[]` | |
| `pairingTags` | `string[]` | derived, not from source data — see `deriveP airingTags()` in `transform.ts` |
| `vegetarian` | `boolean \| null` | `null` means unknown, NOT false — do not treat as false |

 
 
**Why `vegetarian` is `boolean | null` and not just `boolean`:** roughly a third of source rows have `NA` for this field. Defaulting unknown to `false` would misinform anyone actually relying on it for a dietary restriction, `null` preserves "we don't know," which is the honest answer.

## TastingInput
 
What the client sends to `POST /tastings` — deliberately **not** the same shape as `Tasting`.
 
| Field | Type |
|---|---|
| `cheeseId` | string |
| `rating` | number |
| `notes` | string |
 
The client never supplies `tastingId` or `userId` — the server derives both. This prevents a client from logging a tasting under someone else's `userId`.
